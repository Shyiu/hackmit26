# memory-glasses

Smart glasses that help people with dementia find misplaced items. Full spec, architecture, data
model, and build order live in README.md — read that first, it's the source of truth, not this file.

## Repo layout

pnpm workspace. Only `apps/web` and `packages/shared` exist so far; `apps/ios` and
`services/perception` are planned but not scaffolded.

```text
apps/web/         Next.js 16 App Router dashboard, API routes, /sim browser simulator
packages/shared/  zod schemas shared between the web app and (eventually) the perception service
scripts/          db:indexes, db:seed, bench:tts — run from the repo root with pnpm
```

## Commands

```bash
pnpm install
pnpm dev              # apps/web on :3000
pnpm build
pnpm lint
pnpm db:indexes        # needs MONGODB_URI
pnpm db:seed           # needs MONGODB_URI, writes a demo patient + 3 items
```

Copy `apps/web/.env.example` to `apps/web/.env.local` and fill in `MONGODB_URI` at minimum to run
anything that touches the database.

## Status

Bare backbone only: Next.js app, shadcn/ui, Tailwind, the Mongo client helper, and stub API routes
that validate input with the `@memory-glasses/shared` zod schemas and return `501`. No route does
real work yet — see README.md "Build order" for what's next (M1 perception, M2 voice loop).

## Conventions

- API routes live under `apps/web/src/app/api/*/route.ts`, one file per resource, matching the
  table in README.md "API sketch".
- Data shapes are defined once, in `packages/shared/src/schemas/*.ts`, and imported into API
  routes via `@memory-glasses/shared`. Add new fields there first, not ad hoc in a route handler.
- Dashboard pages live under `apps/web/src/app/dashboard/*`, one folder per nav item.
- `apps/web/CLAUDE.md` and `AGENTS.md` are regenerated by `next dev` — don't hand-edit them, and
  do commit them if they change.
