# 5. A 3D room scan that proxies to splat-slam and resolves depth in the browser

Date: 2026-09-20

Status: accepted.

## Context

The dashboard says where an item was last seen in a sentence. We want to show it: a 3D reconstruction of the room with an arrow at the spot. Two sibling repos already do the reconstruction. splat-mesh and splat-lite turn a capture into a textured mesh and a light Gaussian splat, offline. splat-slam is a Python service that takes streamed JPEG frames, runs SLAM and splat training, and publishes camera poses and a growing splat over HTTP. It needs a GPU to keep up, and it has no notion of items or tenants.

A detection is a box on a 2D frame. To place it in 3D we need that frame's camera pose and a depth along the ray through the box.

## Decision

The app proxies to splat-slam at `SPLAT_SLAM_URL` instead of vendoring it. Routes under `/api/scan/live` go through `withTenant`, and a wearer's scene is the newest one named `mg-<patientId>`; every scene route checks that name before it forwards anything. The key, if any, stays on the server.

Depth is resolved client-side. A kept frame's name is the same string as its entry in `cameras.json`, so the caregiver's browser, which already has the splat loaded, builds the ray through the bbox centre, raycasts the splat, and `PUT`s the point to `/api/scan/pins`. We did not add a depth endpoint to splat-slam.

The static demo scan (`mesh.glb`, `splat.spz`, `scene.json`) is bundled in `apps/web/public/scan/room/` instead of object storage.

## Consequences

- splat-slam stays unchanged and runs wherever there is a GPU: locally, or in a Daytona sandbox. A deployed Vercel app needs a public `SPLAT_SLAM_URL`.
- Every frame and splat file passes through a Next.js function, which adds a hop and counts against Vercel's duration and body limits.
- A live pin has no position until a Map tab is open. Until then the viewer draws the arrow along the view ray.
- The position is whatever the browser's raycast hit, so it depends on the splat version loaded at the time. The `PUT` carries the frame name and is refused with 409 when a newer observation has replaced it.
- Static pins are in the GLB's y-up frame and live pins are in splat-slam world coordinates. A pin belongs to one scene and is never converted.
- The static assets add to the repo and the deploy, and are regenerated by hand from splat-mesh `out/mesh.glb` and splat-lite `out/smooth.spz`. Fine for one demo room; more rooms would want object storage.
